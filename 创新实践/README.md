# 创新实践 · 课题 12：机器狗自主侦查

六人三组，十六周。先在仿真里跑通，再上真机。

---

## 选题

**课题 12：基于 SLAM 和目标检测的机器狗自主侦查算法开发**

四足机器狗在安防侦查场景下的完全自主作业：实时定位与建图 → 自主探索未知区域 → 检测目标并记录 → 低电量安全返航。

**为什么选这个题**（在 12 个课题里横向比过一轮）：

| 约束 | 课题 12 的表现 |
|---|---|
| 算力只有共享的八卡 4090 | SLAM 与导航跑 CPU，YOLO 可直接用预训练权重，**基本不抢 GPU** |
| 六人小组 | 天然拆成三个低耦合小组，可并行开工 |
| 硬件依赖 | 实验室有宇树 Go2，档期充足 |
| 交付风险 | **有仿真兜底**——真机走不通时，Gazebo 里的完整流程本身就是可交付成果 |

相比之下，课题 1/2/3/4（灵巧手 + 多卡 VLA 训练）在共享算力下没有可行性；课题 7（VLA 安全）的最小实验单元要求连续数小时占卡且反复迭代，与排队环境不匹配；课题 10/11 虽然最省算力，但学术新意或硬件展示度不足。

**已排除的干扰项**：原始调研文档（`创新实践课程选题介绍.docx`）存在多处虚构或错配的引用，已核实并修正，详见 `docs/选题与规划.md`。

## 分组

三个小组按**层**切，不按模块切——强耦合的东西放同一组，接口清晰的地方才切一刀。

| 组 | 名称 | 职责 | 目录 |
|---|---|---|---|
| G1 | **建图导航** | 仿真环境 · SLAM · 定位 · Nav2 · 避障 | `baseline/g1_mapping_nav/` |
| G2 | **视觉探索** | 目标检测 · 三维定位 · 探索决策 · 异常识别 | `baseline/g2_vision_explore/` |
| G3 | **集成评测** | 真机通信 · 系统集成 · 指标评测 | `baseline/g3_integration_eval/` |

**关键设计**：SLAM 与 Nav2 必须同组（共享 TF 树与 costmap，调试时分不开）；而「探索策略」从导航里摘出来交给 G2——它输出的是「下一个去哪」的目标点，不碰路径规划，属于决策层。
