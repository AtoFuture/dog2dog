## 🔴 高：判据会把失败判成通过 / 把通过判成失败

### H1. `map_growth.py:112` —— P1 第 5 项判据方向反了 ✅ 已修 2026-10-11

```python
"not_constant": {"value": growing, "pass": 0 < growing < steps}
```

`pass` 要求 `growing < steps`，即**至少有一次相邻更新「没长」**。而标签写的是
「增长率非恒定（覆盖率曲线非恒定）」——一个说的是"有没有断"，一个说的是"快不快得均匀"。

**已复现**（照抄第 96–125 行判定逻辑，喂合成数据）：

| 场景 | 在长比例 | 判定 |
|---|---|---|
| 狗一路走、地图每次更新都在长（**正是要证明的**） | 11/11 | **不通过 ❌** |
| 只长一次、之后 11 条完全不变 | 1/11 | **通过 ✅** |
| 只有 2 条地图消息、确实长了 | 1/1 | **不通过 ❌** |

第三行是另一处：`steps = max(len(rows) - 1, 1)`，两条消息时 `steps == 1`，
`0 < growing < 1` 恒假。

**为什么至今没暴露**：仓库 23 个包**没有一个**存到超过 1 条地图消息（全是 AMCL 静态图），
这个判据还没吃过一次真实输入。

**判定方法**：`python3 tools/map_growth.py <含多条 /robot1/map 的 bag>`，
看「更新中在长的比例」是 `N/N` 时是否报不通过。

### H2. `map_growth.py:96-113` —— 只比首末两条，且不要求「增长与运动同期」 ✅ 已修 2026-10-11

`known_gain = end[4] - first[4]` 加上 H1 那条「只要有一次没长」，于是
「跑动期间地图完全没长」也能通过：只要**首图比稳态图稀疏**（首图常只覆盖开局几帧扫描），
第 2 条之后永远不变即满足全部三条。

工具不读真值、不检查增长是否发生在狗移动的时段，所以它回答的是
「地图长过没有」，**不是 P1 第 5 项要的「边走边建图」**。

触发场景正是本项目已吃过一次的失败：控制器没激活 / 狗不动（README 坑 #1）——
那时真值净位移 0，判据却可能报「地图确实在长」。

### H3. `goal_test.sh:18,71,90-95` —— 脚本恒 `exit 0` ✅ 已修 2026-10-11

`set -uo pipefail` **没有 `-e`**；结尾是

```bash
if [ "${CHECK_RC}" -ne 0 ]; then echo "..."; fi
```

bash 对条件为假的 `if` 复合语句返回 0。所以 `goal_check.py` 判 `rc=1`（或 `rc=2`，
包里根本没真值）时，脚本只在 stdout 打一行，**自己仍 `rc=0`**。
任何用 `||`、`&&`、`set -e`、`$?` 串联的自动化都会把「未通过」记成通过。

`ACTION_RC`（第 71 行）取了但从头到尾没参与任何判断，也是死的。

**判定方法**：`bash tools/goal_test.sh ... ; echo $?`，对一轮必然失败的目标也应得 0。

### H4. `goal_check.py:66-68,104-107,149-150` —— 缺 `cmd` 话题时冻结判据静默失效并判通过 ✅ 已修 2026-10-11

`missing` 只警告不中止；`/robot1/cmd_vel_scaled_out` 不在包里 →
`tracks[CMD_TOPIC]` 为空 → `max(..., default=0.0) > CMD_EPS` 恒假 → `windows` 空 →
「冻结 无」→ `ok = error <= 0.30 and longest <= 5.0` 成立 → **通过**。

**已实测**：`goal_check.py <bag_static120> 0.0285 -0.0002`（该包**完全没有**任何速度话题，120 s）
→ stderr 一行 `⚠️ 缺话题` → 「冻结 无（限值 5.0 s）」→ 「判定：通过 ✅ RC=0」。
**冻结这条出口标准等于没判。**

触发场景：手工 `ros2 bag record` 验收、话题改名、只录真值的包。

**根因（已查实）**：接口 04 的冻结话题清单
`g3_integration_eval/config/rosbag_topics.txt` **根本不包含
`/robot1/cmd_vel_scaled_out`**。也就是说，**照清单录包必然缺这个话题**，
判据必然静默失效——这不是"某次录漏了"，是清单本身的问题。
详见 `问题.md` 的跨组问题 X4。

### H5. `goal_check.py:32,66-68,153-156` —— 缺 `amcl_pose` 时报「AMCL 偏差 0.0000 m」 ✅ 已修 2026-10-11

`AMCL_TOPIC` **不在** `missing` 名单里（第 66 行只有 GT 和 CMD）；为空时 `amcl_dev` 保持初值 0.0

**这个数看着是「完美」，不是「没测到」。**

而 README 为 P1 第 5 项规定的流程正是
`start_nav2_isolated.sh --slam`（AMCL 被 slam_toolbox 替掉，**根本没有** `amcl_pose`）
+ `goal_test.sh` → **那份报告必然打 0.0000**。

## ✅ 已解决（原「未解决的设计问题」）· 2026-10-11

**`config/go2_nav2.yaml` 的 slam 参数键名 —— 已定论：两键缺一不可。**

那条 FIX 注释（「顶层键须用相对名，写全限定键会拼成 `/robot1//robot1/`，
rcl 解析失败、bringup 全挂」）**已被实测推翻**。

**做法**：跑真正的 `nav2_scaled.launch.py slam:=True`，30 s 后查
`ros2 param get /robot1/slam_toolbox <参数>`。**不需要仿真** —— 参数在节点构造时
就定好了，与有没有 scan 无关；这也让这个实验从「要起一整套仿真」变成 1 分钟的事。

| 键的写法 | `base_frame` | `scan_topic` | launch |
|---|---|---|---|
| 只有裸键 `slam_toolbox:` | `base_footprint` ❌ | `/scan` ❌ | 存活 |
| 裸键空壳 + `/robot1/slam_toolbox:` | **`base_link`** ✅ | **`velodyne`** ✅ | **存活** ✅ |

结论：**空壳裸键**（满足 `HasNodeParams` 的门禁）**+ 全限定键**（rcl 才认）缺一不可；
且两键版**不会**导致 bringup 全挂。已按此恢复 `config/go2_nav2.yaml`，
并在文件里保留了被推翻的旧注释备查。

**还没做的**：这只证明参数能加载，**没有证明 SLAM 真能建出图**
（那要起仿真走一圈，用 `map_growth.py` 判）。P1 第 5 项仍未验收。
