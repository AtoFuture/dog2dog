# 倒地判据实测：方法 B（三维躯干倾角）

**日期**：2026-09-18
**数据**：`corner1_low` 真实场景 57 帧（彩色 + 深度 + 逐帧标注，含 15 条已倒地轨迹）
**复现**：`tools/validate_method_b.py`
**结论**：🔴 **方法 B 作为「瞬时倾角判据」不成立，不能拿它做倒地判定。**

---

## 1. 为什么必须测

方法 A（检测框长宽比）已实测失败（见 `倒地判据实测-方法A失败.md`，最优工作点召回仅 43%）。
方法 B 是交付物 3 剩下的**唯一判据**，但从写出来起**从没在真实数据上跑过**。

一个从没跑过的判据不能写进交付物。

---

## 2. 先说好消息：两个前置条件都成立

方法 B 成立需要三个条件，前两个实测**都通过了**。

### 2.1 pose 模型在躺姿上能用 ✅

原先的担心是「模型认不出躺着的人」。实测（`yolo11n-pose`，conf=0.25）：

| 标签 | 含义 | 帧数 | 检出人 | 检出率 |
|---|---|---|---|---|
| 0 | 正常活动 | 38 | 35 | 92.1% |
| 1 | 正在倒下 | 4 | 4 | 100% |
| **2** | **已倒地** | 10 | 7 | 70.0% |
| **3** | **已倒地** | 5 | 5 | 100.0% |

**已倒地合计 12/15 = 80%**。检到时关键点置信度中位 **0.94~0.98** —— 不是勉强检到，是检得很实。

label 2 漏的 3 帧是 `185640 / 185646 / 185652`，与之前检测器实测漏的是**同一批**：
人在画面外或几乎不可见。**这类漏检是检测问题，不是判据问题**，不该算进判据的账。

label 0 的 3 个「漏检」是空房间帧（画面里根本没第二个人），是正确行为。

> **结论**：关键点这一环不用再担心了。

### 2.2 重力方向可求，且不需要外参标定 ✅

这里有个**容易想复杂的地方**，值得写下来：

> 方法 B 的躯干倾角是**旋转不变量**。
> `angle(torso, up)` 只要求两个向量在**同一个坐标系**里表达，
> 不要求那个坐标系是 map 系。
> 所以**不需要完整的外参标定** —— 只需要「重力在相机光学系里指向哪」。

本实验用**深度图拟合地面平面**取重力（RANSAC，2 cm 内点），自足、不依赖 IMU，
而且这正是真机上 SLAM/IMU 会给的东西。

实测 57/57 帧拟合成功，跨帧一致性很好：

```
相机高度  1.14 ± 0.22 m
地面法向  (-0.112, -0.939, -0.322)，跨 12 帧标准差 (0.032, 0.006, 0.018)
```

换算过来：相机**下俯约 20°、横滚约 6°**。内点可视化确认拟合的是棋盘格地面，不是床或墙。

> **结论**：方法本身在几何上是干净的。

## 3. 坏消息：逐像素取深度是致命瓶颈

### 3.1 现象

按 `project_depth_bbox` 的做法给四个关键点逐像素取深度，结果是：

```
frame 185459（人坐在床上）
  sh_l 像素(364,340)  深度 1.593 m
  sh_r 像素(434,292)  深度 2.854 m      ← 同一个人的两个肩差 1.26 m
  >>> 三维倾角 87.8°（判为倒地）
```

一个成年人**肩宽就是 0.40 m**。两个肩的深度不可能差 1.26 m。

### 3.2 成因

不是深度图坏了。逐项排除：

* **深度图本身是好的** —— 97.7% 有效像素，量程 0.88~5.9 m，
  307200 像素里 595 个不同取值，且 ΔZ ∝ Z² 的量化规律与视差量化理论值（610 层）**吻合**。
* **对齐也是好的** —— 深度边缘与彩色边缘的互相关峰值在 dx=+1 px。
* **深度图里确实有人** —— 人身上读数 1.6~1.8 m，旁边地面 2.7~3.2 m，是清楚的凹形。
* **问题在关键点** —— pose 模型对**被遮挡的远侧关节**（人背对相机时的另一侧肩/髋）
  只能靠猜，猜出来的点落到了身体轮廓**之外**，逐像素取深度就取到了身后的背景。

中位滤波救不了：窗口里背景占多数时，中位数就是背景。

### 3.3 量化：用人体尺寸当无标签真值

肩宽（0.40 m）、髋宽（0.30 m）、躯干长（0.50 m）是**已知常数**，
与姿态、视角、远近都无关。所以它们可以当**不需要标注的质检真值**。

逐像素 vs 各种窗口取深度：

| 取深度方式 | 肩宽 中位 / 四分位距 | 髋宽 中位 | 躯干长 中位 |
|---|---|---|---|
| 真值（成人） | 0.40 / 小 | 0.30 | 0.50 |
| 单像素 | 0.54 / **0.94** | 0.18 | 0.67 |
| 5×5 中位（现状） | 0.45 / **0.86** | 0.18 | 0.63 |
| 11×11 中位 | 0.45 / 0.90 | 0.18 | 0.59 |
| 21×21 中位 | 0.39 / 0.94 | 0.18 | 0.59 |
| **窗口近端 p5（35×35）** | **0.24** / **0.13** | 0.16 | 0.44 |

**中位数一路都救不了（IQR 0.86~0.94，一半样本差近 1 米）；
近端分位数把 IQR 降了 7 倍** —— 因为人**一定比背景近**，这是遮挡关系决定的。

代价是深度系统性偏近（0.24 < 真值 0.40，**偏小 40%**），所以它必须搭配**区间**质检用。
而**这个偏置正是后面质检门误杀真样本的原因**，见 §4。

## 4. 判据仍然不成立

修好取深度方式、加上人体尺度质检门之后（`tools/validate_method_b.py` 原样输出）：

```
[可分性] ← 这一条比任何阈值指标都重要
  正类倾角: [75, 86, 87, 88, 90, 94]
  负类倾角: [31, 37, 42, 51, 55, 60, 63, 88]
  正类最小值 75°   负类最大值 88°
  >>> **两类重叠** —— 有任何阈值都分不开它们，
      因为有一个正常帧（88°）比最轻的倒地（75°）还高

[阈值扫描]
    60     100%     25%
    65     100%     12%
    75     100%     12%
    80      83%     12%
    90      33%      0%
  结论：**没有**任何阈值同时满足 召回>85% / 误报<10%
```

**一个正常活动的帧给出 88°，比最低的真倒地（75°）还高** —— 分不开。

而且这道质检门丢得太狠，**两类都丢**：

```
label 0（正常）  ：24/33 条被丢弃（73%）
label 1（过渡）  ： 1/4  条被丢弃（25%）
label 2（已倒地）： 4/8  条被丢弃（50%）
label 3（已倒地）： 5/7  条被丢弃（71%）
```

**一半以上的真实倒地拿不到结论** —— 系统会对它们保持沉默。

### ⚠️ 这里有个我没能解掉的内在矛盾，得说清楚

丢弃原因里绝大多数是「**肩宽 0.1~0.24 m，低于下限 0.25 m**」，
也就是**偏小**，不是偏大。

这来自上面那个已声明的偏置：近端 p5 让深度系统性偏近，
而三维距离与深度成正比，于是肩宽被整体压缩。

于是就形成一对**互相拉扯的参数**：

| 取深度窗口 | 深度偏差 | 肩宽中位 | 质检门表现 |
|---|---|---|---|
| 小窗口（5×5 中位） | 无系统偏置 | 0.45（真值 0.40）| 但噪声巨大，IQR 0.86，抓不住错误 |
| 大窗口近端 p5（本次） | **偏近** | 0.37 | 噪声小 IQR 0.13，但**误杀**真样本 |

**要么忍受大噪声，要么忍受系统偏置 —— 本次没有找到一个两头都好的估计器。**
这本身是个需要继续做的工作（例如按窗口内的深度跨度做偏置补偿，
或者用实例分割掩膜把取深度限制在人体内部），
但**它不是本次判决的关键** —— 见下一节。

### 最致命的那一帧

`185819`，倾角 84°，标签是**正常活动**。看画面：

> 人**四肢着地跪趴着**。

内参、深度、关键点**全都没错**（三维肩宽 0.53 m，在人体尺度内）——
躯干确实是水平的。但它不是倒地。

## 5. 已排除的混淆因素

结论最容易被质疑的三点，逐条测过：

### 5.1 内参（最大的疑点）

**数据集没有提供相机标定**，本实验用 fx=fy=615。而倾角对焦距是**一阶敏感**的
（躯干向量 ∝ (A, B, C·f)，f 一变整个方向就变）。

所以把焦距从 350 扫到 700，**每个焦距下各自找最优工作点**：

| fx | 过门轨迹 | 肩宽中位 | 正类倾角 | 负类最大的 3 个 | 最佳工作点 |
|---|---|---|---|---|---|
| 350 | 33 | 0.41 | [60, 74, 76, 77, 78, 88] | [66, 63, 58] | 无 |
| 400 | 31 | 0.39 | [64, 78, 79, 79, 81, 89] | [80, 63, 61] | 63° 100%/5% |
| 450 | 28 | 0.37 | [67, 81, 81, 82, 84, 91] | [82, 63, 58] | 63° 100%/7% |
| 500 | 24 | 0.34 | [70, 83, 83, 84, 86, 92] | [84, 62, 59] | 63° 100%/9% |
| 615 | 20 | 0.30 | [75, 86, 87, 88, 90, 94] | [88, 62, 60] | 无 |
| 700 | 13 | 0.32 | [79, 88, 89, 90, 95] | [90, 77, 63] | 无 |

**每一个焦距下，负类最大值都超过正类最小值。重叠始终存在。**

（另外：用「肩宽=0.40 m」反解焦距得到 264 ± 130，太散定不下来；
但 D435 彩色 HFOV=69.4° 对应 fx≈462，与上表 fx=450 一列的结论一致。）

### 5.2 样本量

只有 15 条已倒地轨迹（过质检门后剩 6 条）。这个量级**不足以**标定阈值 ——
所以上面那些「达标工作点」都不能当作结论。但**重叠的存在**不依赖样本量，
它是一条条具体的帧摆在那里的。

### 5.3 服装

受试者穿深色衣物，是立体匹配的最差情况。这一条**没有排除** ——
换浅色衣物深度会更准，但 5.4 的问题不会因此消失。

### 5.4 根因不在测量，在语义

这是**最重要的一条，且不受上面任何混淆因素影响**：

> **「躯干不水平」和「人倒在地上了」不是一回事。**

跪、蹲、弯腰捡东西、爬行 —— 几何上与倒地几乎无法区分。
`185819` 那条不是测量误差，是**判据真的分不开**。

**换更好的深度相机、更好的姿态模型、更多的训练数据都解决不了这个问题。**

## 6. 已经做的：改成事件判据

判据从「**瞬时倾角**」改成了「**时间上的状态转移 + 事件输出**」，
落在新模块 `g2_core/fall_tracker.py`：

```
每个轨迹一个状态机：UNKNOWN -> UPRIGHT -> LYING
倒地事件 = 见过直立  ->  在 TRANSITION_MAX_S(3s) 内转为水平
                      ->  水平保持 PERSIST_S(2s) 以上
输出：边沿触发，一次事件一条消息
```

时间结构挡掉了单帧判据挡不住的东西：

| 行为 | 时间特征 | 判据 |
|---|---|---|
| 倒地 | 快速转变 → 长时间保持 | ✅ 报 |
| 弯腰捡东西 | 水平不到 1 秒 | ✅ 挡下 |
| 慢慢躺下休息 | 跨越 30°→60° 用了 5 秒以上 | ✅ 挡下 |
| 首次见到时已经躺着 | 没有「直立」这个前状态 | ✅ 挡下（固有边界，见下） |

### ⚠️ 一处必须修正我自己的说法

我最初以为「时间上下文」就够了。**实测不是。**

一个先站着、然后**跪下并保持**的人，同样满足「从直立转为水平并保持」——
时间判据**照样误报**。这一点在 `test_height_gate_is_off_by_default_so_kneeling_still_slips_through`
里被显式钉住了。

真正能把跪和躺分开的是**离地高度**（跪着约 0.5~0.7 m，躺着约 0.2 m）。
所以 `torso_height_m` 也一并进了接口。

**但这个门当前是关着的**，因为实测标定不出来：

```
真倒地（label 2/3）髋部离地  0.28 ~ 1.58 m
正常活动（label 0）  髋部离地  0.22 ~ 1.51 m
```

完全重叠，而且**真倒地那侧出现了 1.58 m 这种不可能的值**（躺在地上的人髋部
不可能离地 1.58 m）—— 是深度测量错误，不是判据问题。

**没标定过的门只会误杀真倒地，所以宁可不关。**

## 7. 接口变更（已完成）

`Detection3D` 加了三个字段（**加字段不改语义，符合契约硬规矩 2**）：

```
builtin_interfaces/Time  onset_stamp      # 异常事件起始时刻
float32                  torso_tilt_deg   # 躯干倾角，原始观测量
float32                  torso_height_m   # 躯干离地高度，原始观测量
```

外加三条**异常类专属的语义规则**，已写进 `baseline/README.md`：

1. **异常类是边沿触发** —— 一次事件一条消息，躺着不重复发。
   所以 G3 统计倒地**次数**要用 `onset_stamp` 去重，用 `stamp` 会把一次算成零次。
2. **异常类不允许 `id = 0`** —— 时间判据依赖轨迹连续性，
   而 `id=0` 表示轨迹还没确认。G2 侧保证：轨迹未确认时不发异常类消息。
3. **`torso_tilt_deg` / `torso_height_m` 是原始观测量，不是判定结果。**

> 第 3 条是这次实测最值钱的一条经验：**正是因为留下了原始量，
> 才发现正负两类的倾角分布是重叠的。** 只看二值结论永远看不出来。
> 有了它，G3 就能在已经录好的 rosbag 上重扫阈值，不必重跑感知、不必重采数据。

## 8. 链路接线与端到端实测（2026-09-18）

`vision_detector` 节点已接上：权重换成 pose 模型即自动启用倒地识别
（`det.keypoints` 为空时整段跳过，纯检测模型下不受影响）。

### 端到端实测结果

```
[统计] 处理 16 帧 ｜ 检测 16 个 ｜ 三维失败 0 ｜ 去重跳过 0 ｜ TF 失败 0 ｜ 已发布 16
[倒地] 可用躯干 113 ｜ 无关键点 0 ｜ 轨迹未确认 37 ｜ 躯干不可用 84 ｜ 事件 0
[DEBUG] 轨迹 9 倾角 89.5° 离地 -0.77 m
```

**链路是通的**：图像 → 关键点 → 取深度 → 三维 → TF → 重力 → 倾角 → 状态机，
每一环都跑到了，倾角数值与离线验证的同一批帧**一致**（185442 → 49.5°，
离线 49°；185448/185523 → 87~90°，离线 76~93°）。

### ⚠️ 但一次真实的倒地事件都没跑出来，原因值得记下来

**① 跨帧 `id` 连续性在这份数据上不成立。**

数据集帧间隔 **5 秒**，人在画面里早就移动了，ByteTrack 的轨迹一直停在
「未确认」状态，`track_id` 绝大多数时候是 `None`。

节点行为是**对的** —— 契约要求轨迹未确认时不发异常类消息，它就一条都没发。
但这意味着**整条时间判据在这份数据上无法被端到端验证**。

给回放器加了 `hold_frames`（同一帧连发 N 次）造准静态序列后，轨迹 id 确实
能拿到了；可是**没有任何一个 id 能跨越「直立 → 倒地」** ——
因为那两次观测之间隔了 5 秒，人被跟踪器当成两个不同目标。

真机上 15~30 fps，相邻帧几乎一样，`n_init=3` 在 0.1 秒内就满足了。
所以**这大概率是数据的问题而不是代码的问题 —— 但没在真实视频上验过，
就不能说它没问题。**

**② 回放里的「离地高度」是假的。**
回放器把相机放在 `cam_z`，而 map 的 z=0 被当作地面 ——
两者对不上时 `torso_height_m` 会整体偏移（实测出现过 -0.77 m）。
真机上这个假设依赖「SLAM 的地图原点建在地面上」，**上机前要确认**。

### 已覆盖的验证

消息构造抽成了模块级纯函数 `build_fall_detection()`，
契约里最容易出错、且出错时不报错的那几条都单测钉住了：

* `onset_stamp` 是事件起始时刻（搞错会让 G3 把一次倒地统计成零次）
* `nanosec` 不会因浮点误差凑到 1e9（那是非法值，DDS 会拒收）
* 高度没测出来发 **NaN 而不是 0**（发 0 等于凭空造出一个最像倒地的数）
* 异常类**拒绝** `id=0`（在产生消息的地方拦，而不是写在文档里靠人记得）

### 还没做的

1. **在真实视频上验跨帧 id 连续性** —— 这是时间判据的地基，
   而目前唯一的证据来自 5 秒间隔的稀疏帧，结论是负面的。
2. **`torso_height_m` 的阈值标定** —— 等深度质量改善
   （现在的误差让真倒地都量出 1.58 m），或者换更好的深度源。
3. **一次真实的倒地事件端到端** —— 需要一个「同一个人在同一个 id 下
   从直立走到倒地」的序列，这份数据给不出来。
