## 二、三组的共同模式

**「不报错、日志干净、功能是坏的」。** 三组都能找到同一类：

| 组 | 例子 |
|---|---|
| G1 | 缺 `cmd_vel` 话题时冻结判据静默失效**并判通过** |
| G2 | `_report_stats` 在 `frames == 0` 时直接 return → 最主流的失效零输出 |
| G3 | 电量读数越出 `[0,1]` 被丢弃，**连 debug 都不打** |

而这次的特别之处是——**好几个判据连"判对了没有"本身都没法信**：
G1 的 `map_growth.py`、G3 的 `navigation_success_rate` 与 `coverage`，
三者都会在真实成功时报失败、在真实失败时报通过。

## 三、跨组问题（不属于任何单组）

### X1. 状态词表有两套，Brain 拿错了一套 🔴

| 位置 | 用的词 |
|---|---|
| G3 内部 `State`（`/g3/state`） | `STANDBY` / `EXPLORE` / `RETURN` / `ESTOP`（大写） |
| G3 对外契约 `/mission_state` | `standby` / `exploring` / `returning` / `estop`（小写，`state_machine.py:43-48`） |
| G2 认的 | `"exploring"` ✅ |
| **Brain 认的** | **`"EXPLORE"`** ❌ —— 恰好是**内部**那一套 |

`mission_brain.py:335` 的 `.upper() != "EXPLORE"` 让 `exploring` 变成 `EXPLORING`，
永远不等。**接上线 Brain 就永远返回 WAIT，不报错。**

### X2. 同一个 action 入口，两组默认值不一致 🟡

| 组 | 默认值 | 解析结果 |
|---|---|---|
| G2 `explorer_node.py:229` | `navigate_to_pose`（相对名） | `/navigate_to_pose`（节点在根命名空间） |
| G3 `state_machine_node.py:53` | `/robot1/navigate_to_pose`（绝对名） | 正确 |

09-26 那次跑通是因为**启动时覆盖了**（G2 日志首行 `nav=/robot1/navigate_to_pose`）。
按默认值起就发不到 Nav2，且不报错。

### X3. 安全半径没有单一事实来源 🟡

契约要求「探索的安全半径与 G1 的 `inflation_radius` 同源并写进冻结参数」。
实际：G2 侧 `safety_radius_m = 0.45` 硬编码在 `ExplorerParams` 里、
**节点连 yaml 都没有**；G1 侧在 nav2 配置里。两边没有共同来源。

### X4. 接口 04（统一 rosbag 话题清单）漏掉了三个问题各自的依赖 🔴

接口 04 的载体是 `g3_integration_eval/config/rosbag_topics.txt`（第 1 周冻结）。
逐条比对下来，**它漏掉的恰好是下面三件事各自依赖的话题**：

| 实际需要的话题 | 在清单里？ | 依赖它的东西 |
|---|---|---|
| `/robot1/cmd_vel_scaled_out` | ❌ **不在** | **G1 H4 的根因**——`goal_check.py` 靠它判「有指令但不动」的冻结段；不在清单里就不会被录，判据于是静默失效**并判通过** |
| `/detections_3d` | ❌ **不在** | **接口 03 本身**（G2 的核心交付物）。清单从没包含它 → **三次联调 bag 里一条检测话题都没有**，机械地解释了「检测链路从未进联调」 |
| `/g3/sim_battery_state` | ❌ **不在** | 09-26 两次低电量返航实验用的就是它。也就是说**那两次实验录的话题在冻结清单之外** |
| `/robot1/navigate_to_pose/_action/*` | ⚠️ 只有**不带命名空间**的版本 | 清单写的是 `/navigate_to_pose/_action/feedback`，靠一句注释「record_bag.sh replaces these defaults for a namespaced action」补救；而 `evaluate_bag` 统计 observed goal 正是靠这个 topic，合并后的环境用的是 `/robot1/navigate_to_pose` |

**这不是四条孤立的小疏漏**——它说明接口 04 冻结之后，
三组各自的实现都在清单之外长出了新话题，而没有人回头改清单。
于是「按清单录包」这件事本身就会漏掉关键数据，而且不漏在任何人的视野里。

**判定方法**：把 `rosbag_topics.txt` 与 `evaluate_bag.py` / `goal_check.py` /
detector 的实际话题名做一次三方求差，缺的补进去并升版本。

> 补一条相关：`evaluate_bag.py:23,125,243` 把 `/g3/return_event` **硬编码**，
> 而 `state_machine_node.py` 有 `return_event_topic` 参数、
> 电量话题与 navigate action 也走命令行——**同一份清单存在多个来源**，
> 改名时任一处不同步就静默降级。
