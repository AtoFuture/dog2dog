## 一、⚠️ 中文路径会导致 ROS2 编译失败

**这是全队都会踩的坑，而且报错信息极具误导性。**

仓库顶层目录名是 `创新实践`（中文）。ROS2 的构建链（colcon → CMake → rosidl）
**无法处理非 ASCII 路径**，症状是：

```
CMake Error at .../rosidl_generator_c_generate_interfaces.cmake:69 (message):
  Target dependency
  '/baseline/interfaces/build/vision_interfaces/rosidl_adapter/.../Detection3D.idl'
  does not exist
```

注意那个路径 —— **`/home/wy/data1/创新实践` 整段被吃掉了**，只剩 `/baseline/...`。
看起来像「文件没生成」，实际是路径编码在 CMake 变量展开时被截断。
不知道这个坑的话，能在上面查半天。

### 实测对照（同一挂载点，只差目录名）

| 路径 | 结果 |
|---|---|
| `/home/wy/ascii_ws/` | ✅ colcon build 通过，5.17 s |
| `/home/wy/data1/创新实践/` | ❌ 失败 |

### 无效的绕法

**软链接不行** —— colcon 会解析回真实的中文路径：

```bash
ln -s "/home/wy/data1/创新实践" /home/wy/proj   # 从 /home/wy/proj 编译仍然失败
```

### 可行的绕法：bind 挂载到 ASCII 路径

把中文目录 bind 挂到容器内的纯 ASCII 路径上，容器里看到的就是**真正的 ASCII 路径**：

```bash
-m "/home/wy/data1/创新实践:/home/wy/project"
```

之后在容器内用 `/home/wy/project/...` 编译即可通过。两个路径指向同一份文件。

> **长期建议：把 `创新实践/` 改成 ASCII 目录名**（如 `innovation-practice`）。
> 容器外、CI 里、别人机器上都能直接用，不必每处都挂载。这需要全队同意后统一改，
> 因为它会改变仓库结构。**在决定之前，容器内的编译一律走 `/home/wy/project`。**

## 二、ROS2 环境：用 enroot 容器

### 为什么不用 Docker

这台机器 **Docker 是装好的**（28.5.1，守护进程在跑），但 `/var/run/docker.sock`
权限是 `root:docker`，而 `docker` 组只有 `gzl ccb lmx gny hmb cpc` 六个人 ——
**`wy` 不在里面，而加入 docker 组需要 sudo**。

enroot 是 NVIDIA 为 HPC 场景做的**无特权容器工具**，本机已装（3.5.0），
设计上就不需要 root。它从 Docker Hub 拉镜像，用自己的运行时跑。

### 已搭好的环境

```
镜像 ros:humble（254 MB）→ 容器 ros+humble（约 1.7 GB）
位置：~/.enroot/
入口：~/.enroot/ros
```

已在基础镜像上补装了：`cv_bridge`、`nav2_msgs`、`image_transport`、`python3-pip`。

### 用法

```bash
~/.enroot/ros                          # 进交互式 shell（已 source ROS 环境）
~/.enroot/ros ros2 topic list          # 直接跑命令
~/.enroot/ros colcon build             # 编译
~/.enroot/ros --root apt install -y x  # 装系统包（需要 root）
```

容器内 `/home/wy` 和 `/tmp` 与宿主机是**同一份文件**（bind 挂载），
所以仓库在容器里改完立即在宿主机生效，不用复制。

### ⚠️ enroot 的几个坑（都踩过了）

| 坑 | 症状 | 解法 |
|---|---|---|
| 系统配置写死给别人 | `Permission denied: /var/tmp/enroot-data-herd/...` | `/etc/enroot/enroot.conf` 是给 `herd` 配的；用环境变量覆盖（`~/.enroot/env.sh` 已处理）。enroot 的 `config::export` 是 `${VAR:-default}` 形式，**环境变量优先于配置文件** |
| `-m` 的参数是挂载规格不是文件 | 传 fstab 路径不报错，但容器里是空目录 | 用 `-m 源:目标` 的冒号形式 |
| 根文件系统默认只读 | `touch: Read-only file system` | 加 `-w` |
| 容器内默认非 root | apt 装不了包 | 加 `-r` 映射为 root |

### 宿主机上没有 ROS2

查证过程（免得有人再查一遍）：

- `/opt/ros` 不存在；全盘找不到 `ros2` 可执行文件与 `librcl.so` / `_rclpy_pybind11.so`
- `dpkg -l` 无 `ros-*` 包；**apt/dpkg 日志里从来没有 ROS 的安装或卸载记录** → 从未 apt 装过
- 唯一痕迹：`/data4/hmb_code/` 的工作空间引用了 `/opt/ros/humble`，
  但那是 9月10日 建的，多半在容器里编好拷出来的

**结论：ROS2 只存在于容器里。** 想用就得走容器。

### ⚠️ 这不是团队长期方案

- 目前只有 `wy` 一个人搭了 enroot 容器。**G1 要 Gazebo/gz-sim + Nav2 + RTAB-Map、
  G3 要编译 `unitree_ros2`**，都需要 ROS2，各搭一套会导致三组环境不一致、联调困难。
- **建议推动管理员原生安装 ROS2 Humble**，或统一走容器方案。
