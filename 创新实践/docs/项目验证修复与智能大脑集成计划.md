# 项目验证、修复与智能大脑集成计划

> 课题：基于 SLAM 和目标检测的机器狗自主侦查  
> 制定日期：2026-09-23  
> 当前基线：`develop` @ `6da3dee`  
> 本文用途：统一后续修复顺序、大模型接入边界、跨组接口和验收标准。

---

## 1. 目标与成功画面

最终演示不是先建完图再找目标，而是一个持续运行的在线任务：

1. 机器狗从基站出发，SLAM 持续更新地图与位姿。
2. 探索模块持续从当前地图提取 frontier，产生候选目标点。
3. “智能大脑”根据任务意图、探索进度、目标证据、电量和安全状态，选择下一个高层动作。
4. Nav2 规划路径并避障；机器狗移动时，SLAM 和检测不停止。
5. 发现任务目标后，进行多帧确认，记录目标类别、置信度、`map` 坐标、时间和抓拍图。
6. 按任务要求继续探索或返航；低电量、急停和通信超时始终拥有更高优先级。
7. 返回基站后自动生成地图、目标清单、运行轨迹、覆盖率曲线和任务报告。

### 最小可演示任务

> 输入：“在未知仓库中寻找一名人员，发现后记录位置并返航。”  
> 输出：实时地图 + 探索轨迹 + 目标坐标/抓拍图 + 自动返航 + 指标报告。

## 2. 当前基线判断

| 部分 | 已有成果 | 当前缺口 |
|---|---|---|
| G1 建图导航 | 仿真传感器链路、二维地图、点云/OctoMap/RTAB-Map 产物、Nav2 规划证据 | 早期导航成功受虚假里程计污染；最新记录仍有 AMCL 漂移与 DWB 零速，尚无可信运动闭环 |
| G2 视觉探索 | 检测、投影、frontier、状态机、`NavigateToPose` 客户端、假 action server、倒地时序链路 | 真机无深度相机，当前三维人体链路不能原样上机；尚未在真 Nav2 上做持续探索闭环 |
| G3 集成评测 | 状态机、低电量触发、离线 rosbag 评测、覆盖率与导航结果统计 | 返航 goal 真实发送被硬禁用；逻辑 ESTOP 不等于物理急停；返航成功率仍不可用 |
| 版本与交付 | G2 已大量进入 `develop`；G3 有 4 个完整功能提交 | G3 尚未合入 `develop`；G1 大量脚本、配置与实验产物未跟踪；顶层进度表过期 |

结论：当前应从“各自增加功能”转入“关闭关键闭环”。大模型接入应与系统联调并行进行，但不得掩盖 G1 导航基座尚未通过的事实。

## 3. 总体架构

```text
用户任务 / 演示脚本
            │
            ▼
┌─────────────────────────┐
│ Mission Brain（大模型 + 确定性护栏）│
│ 理解任务、候选点排序、决定继续/  │
│ 确认/返航、生成可读任务报告     │
│ 不直接发 cmd_vel，不绕过安全状态机 │
└───────────┼─────────────┘
│                                      │
▼                                      ▼
G2 探索/感知                         G3 任务状态/安全
frontier 候选集                     STANDBY/EXPLORE/
Detection3D + 抓拍                    VERIFY/RETURN/ESTOP
│                                      │
└──────────────────┬──────────────────┘
                   ▼
             G1 Nav2 执行层
        路径规划 / 避障 / 动作结果
                   │
                   ▼
       SLAM + TF + 传感器 + 机器狗
          （全程持续运行）
```

### 3.1 数据面与决策面分离

- **数据面**：SLAM、TF、图像、点云、目标检测和 Nav2 反馈按原有 ROS2 频率运行。
- **决策面**：大模型只在任务开始、新 frontier 集生成、目标候选被发现、导航失败、电量跨阈值等事件上调用。
- 大模型不应每帧调用，也不应进入导航控制回路。目标决策建议频率不高于 0.2–1 Hz，调用期间保持当前安全动作。

### 3.2 大模型的职责

**应做：**

- 把自然语言任务解析为结构化目标：目标类别、数量、找到后的行为、最大时间、返航策略。
- 在 G2 生成的安全 frontier 候选集中做高层排序，可利用语义线索、历史失败、预计收益和路径成本。
- 根据已验证的检测证据决定“继续搜索、前往复核点、任务完成或返航”。
- 把结构化运行数据生成人可读的任务摘要。

**不应做：**

- 不直接输出关节指令或 `cmd_vel`。
- 不自行生成地图坐标；只能从 G2/G1 给出的候选 ID 中选择。
- 不把语言推理当成检测证据；“找到目标”必须引用真实 `Detection3D.id` 和时间戳。
- 不能覆盖低电量、ESTOP、通信超时、地图/TF 失效等硬护栏。

## 4. 大模型接入方案

### 4.1 双路径、同一接口

实现一个与供应商无关的 `BrainProvider` 接口，支持：

| 路径 | 用途 | 优点 | 主要风险 |
|---|---|---|---|
| API 模型 | 快速完成 MVP 和高质量语言决策 | 开发快、推理能力强、无本地显存压力 | 网络、时延、费用、数据出域 |
| 本地模型 | 断网演示、私有数据、可控延迟 | 可离线、调用成本固定 | 部署、显存、散热与生成质量 |
| 确定性回退 | 任何模型超时、报错或输出非法时 | 保证任务不因模型失联而停止 | 策略较朴素 |

建议顺序：**API 先跑通接口和任务闭环，再接本地模型，最后保留确定性 frontier 回退。** 演示时可根据网络和设备状态选择 provider，不修改上层 ROS2 逻辑。

### 4.2 本地部署位置

1. **优先：局域网 GPU 服务器**  
   将推理服务与 ROS2 节点分离，对机器狗提供与 API 相同的 HTTP 接口。适合快速试验更大模型，不占用 Orin 的感知资源。
2. **备选：Go2 Orin NX 上的量化小模型**  
   只处理结构化文本与少量候选点，不在同一进程内处理原始点云或高帧率视频。模型大小以真机显存、温度和延迟实测为准，不预先锁死品牌。

### 4.3 受限输出协议

模型只允许返回下列动作之一：

```json
{
  "action": "SELECT_FRONTIER | VERIFY_DETECTION | CONTINUE | COMPLETE | RETURN | WAIT",
  "candidate_id": "frontier-17",
  "evidence_ids": [42],
  "reason": "brief human-readable explanation",
  "confidence": 0.86
}
```

执行前由确定性校验器检查：

- `action` 必须在白名单内。
- `candidate_id` 必须来自当前候选集且未过期。
- `evidence_ids` 必须对应真实检测记录。
- 非 `EXPLORE` 状态下拒绝所有新探索目标。
- 低电量、ESTOP、TF 过期或定位不可用时，模型输出不得执行。
- 模型超时、JSON 无效或连续两次被拒绝时，自动回退至 G2 现有的确定性 frontier 评分。

### 4.4 建议新增的 ROS2 边界

| 接口 | 方向 | 内容 |
|---|---|---|
| `/mission/request` | UI/G3 → Brain | 自然语言任务与任务 ID |
| `/mission/plan` | Brain → G3 | 结构化任务约束，由 G3 验证后激活 |
| `/mission/state` | G3 → G2/Brain | `standby/exploring/verifying/returning/estop`，`transient_local` |
| `/exploration/candidates` | G2 → Brain | 候选 ID、坐标、信息增益、路径成本、失败次数 |
| `/brain/decision` | Brain → G2/G3 | 受限动作、候选 ID、证据 ID、原因、延迟 |
| `/mission/events` | 全系统 → G3 | 状态转移、检测、goal 与安全事件，用于 rosbag 和评测 |

注：现有 `/mission_state` 与建议新名 `/mission/state` 不应并存。接口评审时二选一，然后一次性修改 G2/G3，并将状态语义写入共用接口文档。

## 5. 分阶段验证与修复计划

### P0：版本与证据固化（1–2 天）

**任务**

- 将 `g3/integration` 的 4 个功能提交评审后合入 `develop`。
- 将 G1 的必要配置、启动脚本、小型示例地图和实验索引纳入版本管理。
- 1.5 GB RTAB-Map 数据库、rosbag 等大文件移至团队共享存储；仓库仅保留 URL/路径、SHA-256、生成命令和元数据。
- 更新顶层 README 的进度勾选和实际话题名。
- 建立单一的“环境自检”命令，报告 ROS2、Nav2、`cv_bridge`、PyYAML、消息包和 GPU 是否可用。

**出口标准**

- 新工作目录从 `develop` 可构建 G2/G3。
- 不依赖任何人的未跟踪脚本即可按文档重现最小测试。
- 大文件有存储位置与校验值，不直接进普通 Git 历史。

### P1：G1 可信运动与建图闭环（3–5 天）

**任务**

1. 在独占的 ROS Domain/时间窗中启动干净仿真，确保 controller、odom、bridge、Nav2 节点单例。
2. 修复或隔离足端里程计幻觉；评测时同时记录 odom、AMCL 和 Gazebo ground truth。
3. 解决 AMCL 漂移与 DWB 零速，不得再仅以 action 的 `SUCCEEDED` 判定真实到达。
4. 连续执行至少 5 个目标点，包含转弯、死胡同和遮挡区。
5. 导航期间保持 SLAM 运行，证明地图能边走边更新。

**出口标准**

- ground truth 上到点误差 ≤ 0.30 m 的成功率 ≥ 4/5。
- 静止 120 s 时虚假位移 ≤ 0.02 m。
- 不出现重复控制器、留存速度指令或超大异常 costmap。
- rosbag 中同时包含地图、TF、Nav2 goal/result 和 ground truth。

### P2：G2 边建图边探索（3–5 天）

**任务**

- 对接 G1 实际 `/map`、TF 和 `NavigateToPose` action，确认话题名、frame 名和 QoS。
- 用持续变化的 OccupancyGrid 运行 frontier 探索，不再只用静态假地图。
- 实装 G3 的 mission state 停手接口；`returning/estop` 时取消在飞探索 goal，不再发新 goal。
- 对真 Nav2 重跑抢占探针，记录旧 goal 的真实终态。
- 为“暂无候选、暂时导航失败、真正探完”分别保留可观测事件。

**出口标准**

- 机器狗在无人点选的情况下连续完成至少 5 个 frontier goal。
- 探索期间地图可通行区域持续增长，覆盖率曲线非恒定。
- 收到 `returning` 后 1 s 内停止发送新探索 goal，不与返航目标争抢 Nav2。

### P3：目标寻找与证据链（3–7 天，可与 P2 并行）

**任务**

- 先以仿真 RGB-D 或已有带深度数据验证“移动中检测 → `map` 系定位 → 抓拍 → 去重”。
- 对真机无深度相机问题做书面决策：
  - A：加装 D435i 类 RGB-D，保留现有三维链路；
  - B：前视图像 + L1/MID-360 点云融合，重写取深度步骤；
  - C：仅做二维目标检测，三维位置和倒地识别降级为仿真交付。
- 建议优先 A；若无硬件采购权限，则用 B 做研究性方案、C 做保底。
- 目标确认采用“检测置信度 + 稳定 track ID + 连续帧/时间门”，大模型只能请求复核，不能伪造确认。

**出口标准**

- 移动建图期间产生至少 1 个可复现的真阳性目标事件。
- 该事件能从 `Detection3D` 追溯到抓拍图、原始帧、TF 和机器人轨迹。
- 记录位置误差；仿真目标建议首轮门槛 ≤ 0.50 m，后续再收紧。

### P4：Mission Brain MVP（4–7 天）

> 进度更新（2026-09-23）：DeepSeek `deepseek-flash` provider、受限 JSON
> 协议、候选/证据校验、确定性回退和 ROS2 JSON 话题节点的基础版已落盘。
> 尚待使用轮换后的密钥做一次真实 API 冒烟测试，并与 G2 真实
> frontier 候选话题联调。

**任务**

1. 实现 provider-neutral 客户端和受限 JSON 协议。
2. 实现确定性校验器、超时、重试、熔断与 frontier 回退。
3. 向模型只提供结构化摘要：任务、mission state、电量、定位健康度、探索进度、候选 frontier、最近检测和历史失败。
4. 先接 API provider，再接本地 provider，两者用相同回放集评测。
5. 保存每次输入摘要、模型原始输出、校验结果、最终执行动作、延迟与 provider，但不把 API 密钥写入日志。

**出口标准**

- 固定回放集上 100% 输出可解析或安全回退，不得因格式错误使任务停机。
- 故意注入超时、HTTP 失败、非法候选 ID、无证据 `COMPLETE` 等情况，护栏全部拦截。
- Brain 不直接发布 `cmd_vel`，不直接调用底层运动接口。
- provider 在运行期可配置切换，上层 ROS2 接口不变。

### P5：全链路闭环与返航（5–7 天）

**任务**

- 打通：任务输入 → Brain 解析 → frontier 选择 → Nav2 执行 → SLAM 更新 → 目标检测 → 复核/完成 → 返航。
- 实现 G3 真实返航 goal 发送，但首先只在隔离仿真域解锁。
- 为返航 goal 增加显式 mission/goal 标记，使 `return_success_rate` 可计算。
- 按“ESTOP > 通信/定位故障 > 低电量返航 > 目标复核 > 探索”固定优先级，Brain 不参与改写。
- 对每次运行自动落盘 rosbag、任务事件和指标 JSON/CSV。

**出口标准**

- 仿真中连续 3 次完成“边建图边找目标并返航”，无人手动点 goal。
- 目标不存在时，系统能正确报告探索完成/超时，不伪造发现。
- 模型服务中断后，系统自动转入确定性策略或安全返航。
- 低电量触发后无新探索 goal 抢占返航 goal。

### P6：真机分级上车（仿真连续通过后）

1. 静态通信与传感器录包，不接管运动。
2. 低速遥控建图，验证地图、TF、检测和日志。
3. 有人监护的单目标 Nav2，物理急停始终可用。
4. 有人监护的两个 frontier 探索，限速、限区域、限时。
5. 启用 Brain，但先只允许其建议动作，人工确认后执行。
6. 在多次零越界后才允许自动执行高层动作。

## 6. 必测场景矩阵

| 场景 | 期望行为 | 主要证据 |
|---|---|---|
| 未知地图、目标存在 | 持续建图和探索，发现后记录并按任务返航 | 地图增长曲线、Detection3D、抓拍、返航终态 |
| 未知地图、目标不存在 | 探索完成或超时，明确报告未找到 | `NO_FRONTIER`/超时事件，无虚假证据 |
| 目标短暂误检 | 要求复核或继续探索，不立即完成任务 | track ID、连续帧、事件日志 |
| Nav2 目标不可达 | 拉黑或降权候选点，重新规划 | goal 终态、失败次数、新决策 |
| 低电量发生在探索中 | G2 停手，取消探索 goal，G3 发返航 goal | mission state 时序、goal UUID、返航结果 |
| 模型 API 超时/断网 | 不停机，回退 frontier 或安全返航 | 熔断记录、回退策略、任务连续性 |
| 模型输出非法坐标/ID | 校验器拒绝，不发送 Nav2 goal | 拒绝原因和零运动指令 |
| 定位丢失或 TF 过期 | 停止新决策，减速/停机，等待恢复或人工接管 | TF 年龄、定位健康度、安全状态 |
| ESTOP | 立即停止任务动作，Brain 无权恢复 | 物理/逻辑急停记录、无新 goal |

## 7. 指标与比较实验

### 7.1 系统指标

- 探索覆盖率及覆盖率-时间曲线。
- 目标检出率、误检率、首次发现时间、目标定位误差。
- 导航 goal 成功率、平均路径长度、重规划次数。
- 返航成功率、触发到停止探索的延迟。
- 系统任务成功率和总耗时。

### 7.2 Brain 指标

- 决策延迟 P50/P95、超时率、格式错误率、护栏拒绝率、回退率。
- 单次任务 API 调用次数/成本，或本地推理显存、温度与吞吐。
- 引用真实证据的决策比例；无证据完成任务必须为 0。

### 7.3 必做对照组

| 组别 | frontier 选择 | 任务决策 |
|---|---|---|
| Baseline | G2 现有确定性打分 | 确定性状态机 |
| API Brain | 模型从同一候选集中排序 | 大模型 + 硬护栏 |
| Local Brain | 本地模型从同一候选集中排序 | 大模型 + 硬护栏 |

三组必须使用同一地图、同一目标布置和同一随机种子。否则只能展示“接上了大模型”，无法说明它对探索效率有贡献。

## 8. 分工建议

| 组 | 主责 | 与 Brain 的边界 |
|---|---|---|
| G1 | 可信建图、定位、Nav2、ground truth 验收 | 提供导航可达性和结果，不接受 Brain 直接速度指令 |
| G2 | frontier 候选集、检测证据、目标复核 | Brain 可排序候选，不得伪造 frontier 或 Detection3D |
| G3 | Mission Brain 节点、任务状态、安全优先级、日志与评测 | 拥有 provider、校验器、回退和任务事件记录 |
| 全队 | 接口冻结、实验场景、验收见证 | 共同决定 mission state 和 Brain 输出协议 |

## 9. 立即需要全队拍板的事项

1. **真机三维感知路线**：加装 RGB-D、激光点云融合，或二维降级。
2. **Mission state 接口**：话题名统一为 `/mission_state` 还是 `/mission/state`，是否增加 `verifying`。
3. **找到目标后的行为**：立即返航、原地报告后继续，还是前往复核点。建议作为任务参数，默认“确认后返航”。
4. **Brain 的主责组**：建议归 G3，因为它属于任务状态与集成层，不属于 Nav2 控制层或检测算法层。
5. **API 数据边界**：是否允许上传图像。建议 MVP 只发结构化文本；如需多模态复核，单独评审脱敏、带宽和成本。

## 10. 项目级 Definition of Done

只有同时满足下列条件，才可宣布“自主侦查系统完成”：

- [ ] 机器狗在未知地图中移动时，SLAM、探索和目标检测同时运行。
- [ ] 全程不需人工在 RViz 中点选导航目标。
- [ ] “找到目标”有可追溯的检测证据，而不是大模型文本推测。
- [ ] Brain 能用 API 或本地模型完成至少一种部署，且具备确定性回退。
- [ ] Brain 不能绕过安全护栏直接控制机器狗。
- [ ] 低电量返航不与探索 goal 打架，仿真返航成功率达到 100%。
- [ ] 仿真中至少连续 3 次完整闭环成功，每次都有 rosbag 和指标报告。
- [ ] 真机上完成逐级安全验证；若真机受硬件限制，则明确列出仿真与真机交付边界。
- [ ] `develop` 包含可复现代码、配置、测试和文档；大文件有独立存储索引。
