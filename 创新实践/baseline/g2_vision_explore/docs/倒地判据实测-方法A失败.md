# 实测报告：长宽比判据（方法 A）在低机位下不成立

> 2026-09-17 ｜ G2 视觉探索
> 上一篇：[`躺姿召回实测报告.md`](躺姿召回实测报告.md)（检测「有没有人」）
> 本篇：检测「人是不是倒地了」—— 交付物 3 的真正验收口径

---

## 一、结论先行

**方法 A（检测框长宽比）在低机位下无法区分站立与倒地。**

在计划的判据（归一化高宽比 < 0.6 判倒地）下：
**倒地召回仅 43%，即漏掉了 57% 的真实倒地。**

这不是阈值没调好 —— 扫描了 0.4 到 1.2 **全部阈值**，以及 -20° 到 +20° 的
**全部俯仰角归一化**，**没有任何工作点**能同时满足「检出率 > 85%、误检率 < 10%」。

| 阈值 | 倒地召回 | 正常帧误报 |
|---|---|---|
| 0.6（计划采用） | **43%** | 0% |
| 0.9 | 49% | 12% |
| 1.0 | 69% | **27%** |
| 1.2 | 83% | **60%** |

要么漏一半，要么误报六成。**没有中间地带。**

---

## 二、证据：两类分布严重重叠

```
正常(label 0)   n= 89  中位数 1.14  [四分位 0.99~1.34]  范围 [0.68, 2.94]
已倒地A(label 2) n= 17  中位数 0.94  [四分位 0.50~1.03]  范围 [0.38, 1.42]
已倒地B(label 3) n= 15  中位数 0.78  [四分位 0.39~0.97]  范围 [0.35, 1.39]
```

看**范围**那一列：倒地样本的比率能高到 **1.42**（接近正方形），
正常样本能低到 **0.68**。中位数虽然分得开（1.14 vs 0.78），
但**单帧的离散度远大于两类之间的差距** —— 这正是「重叠」的量化含义。

俯仰角归一化救不了：它的修正是除 `cos(θ)`，20° 也只差 6%，
而两类之间的差距是 43% 召回 vs 83% 召回的量级。

---

## 三、为什么会这样

### ① 低机位的前缩（这是主因，且对我们的项目同样成立）

相机在 35 cm 高度、接近水平。人躺在地上时：

- **横躺**（身体垂直于视线）→ 投影又宽又扁，长宽比低 ✓
- **纵躺**（身体沿光轴，脚朝相机）→ **极度前缩**，投影可能接近方形甚至偏高 ✗

计划里点名的「沿光轴躺倒」是最难的情况，实测确认它在样本里占了相当比例。

### ② 这个数据集的「正常」类别里包含坐姿

受试者是**轮椅使用者**。数据集 README 说明标签为
`usual / falling / caution / emergency`，而 `usual` 里包含**坐在轮椅上**的姿态 ——
那个投影同样是「矮而方」的，与倒地几乎无法用长宽比区分。

> ⚠️ **这一条是数据集特有的，对我们的项目是「过度悲观」**：
> 侦查场景要分的是「站着的人」vs「躺在地上的人」，比
> 「轮椅坐姿」vs「倒地」容易得多。所以**方法 A 在我们场景下未必失败得这么彻底** ——
> 但也**没有任何理由相信它够用**，尤其在低机位 + 前缩这两个因素同样存在的前提下。

---

## 四、对计划的影响：方法 B 从「加固」变成「必需」

计划 §4.4 原设计是：

```
方法 A（长宽比） 快速粗筛  →  方法 B（三维姿态）确认
```

这个设计**成立的前提是 A 能把大部分真阳性筛出来**。实测证明它筛不出来 ——
在误报为 0% 的阈值下它丢掉 57% 的真阳性。**A 不能做筛子，它会把信号一起扔掉。**

**修正后：**

| | 原计划 | 修正后 |
|---|---|---|
| 方法 A | 粗筛（必做） | **降级为辅助信息**，只作为日志/可视化参考，不参与判定 |
| 方法 B | 确认（做） | **唯一的判据** |

---

## 五、方法 B 的验证在哪儿做（重要）

我本想在这个数据集上直接把方法 B 也验了 —— 它有深度流。但撞上一个障碍：

**该数据集的 RGB 是 1024x1024，深度是 480x640，两者视场不一致**
（RGB 是裁剪过的：深度图里能看到更宽的视野）。而数据集**没有提供裁剪参数**。

要把 RGB 上的关键点准确映射到深度上做三维反投影，必须先知道这个裁剪关系。
用「缩放到同尺寸」硬凑会引入未知的几何误差，**做出来的结论不可信**。

> 这是**数据集特有的问题，不是项目会遇到的**：真机上 `align_depth:=true`
> 直接给出与彩色对齐的深度图，内参从 `camera_info` 拿，不存在这个问题。

**所以方法 B 的验证应该在仿真里做**，这也是项目计划原本就定的路线：

- gz-sim 里内参、外参、TF、地面平面**全部精确已知**
- 可以造**精确的真值**：人的躯干倾角是多少度，直接知道
- 可以**定向构造**最难的情况（沿光轴躺倒、部分遮挡、远距离），而不是靠数据集碰运气

建议：等 G1 的仿真环境可用后，在仿真里做方法 B 的定量验证；
数据集这边只保留「检测人」这个已验证的结论。

---

## 六、这次实测确认与推翻的东西

| 项 | 结论 |
|---|---|
| 预训练检测器能否检出躺姿的人 | ✅ **能**。可见倒地帧召回 32/32 = 100%（见上一篇） |
| 模型代际 / 规模 / imgsz / conf 是否影响检出 | ❌ 都不影响，用最小的 `yolo26n @640` 即可 |
| **长宽比能否判倒地** | ❌ **不能**。低机位下漏 57% |

坏消息是判据要重做；**好消息是判据的输入是可靠的** ——
检出这一步没问题，问题只出在「拿到框之后怎么判」。
而方法 B 的输入（关键点 + 深度）在真机上都是现成的。
