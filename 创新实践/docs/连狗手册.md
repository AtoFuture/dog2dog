## 二、开连（三步）

```bash
# ① 确认狗在线（狗通电后机载电脑要几分钟才起来）
tailscale status | grep go2-dock

# ② SSH 进去
ssh unitree@100.121.216.97
```

口令：**见群内，不要写进仓库。**

主机密钥首次连接时接受一次即可（`StrictHostKeyChecking=accept-new`）。

```bash
# ③ 进去之后，环境要这样 source 才看得到话题
source /opt/ros/foxy/setup.bash
source ~/cyclonedds_ws/install/setup.bash
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI="file://$HOME/cyclonedds_ws/cyclonedds.xml"

ros2 topic list        # 约 146 个话题
```

**这三条 source/export 缺一不可**，否则 `ros2 topic list` 是空的。

## 三、⚠️ 狗上是 **Foxy**，不是 Humble

```
/opt/ros/foxy      ← 狗上（另有 ROS1 noetic）
```

服务器的容器是 **Humble**。由此带来两个具体的坑：

| 坑 | 说明 |
|---|---|
| **`--once` 不存在** | `ros2 topic echo <t> --once` 是 **Humble 才有**的写法。Foxy 里要用 `timeout 15 ros2 topic echo <t> \| head -n 20` |
| **读宇树消息要先 source 到 `unitree_go`** | 不 source 到消息包，`ros2 topic echo /sportmodestate` 会抛 `get_msg_class` 的 traceback —— 那是**环境问题，不是没数据** |

> ⚠️ **跨版本（Foxy ↔ Humble）的 DDS 通信与代码兼容性都没验证过**，这是全队要拍板的事。

## 六、失败对照表

| 症状 | 按顺序先怀疑 |
|---|---|
| `tailscale status` 看不到 `go2-dock` | 狗没通电，或机载电脑还没起完（**要几分钟**） |
| SSH `Permission denied` | 口令不对（**SSH 故意不区分"用户名错"和"口令错"**） |
| 进去了但 `ros2 topic list` 是空的 | **三条 source/export 没做全**（最常见） |
| 话题在，但 `ros2 topic echo` 抛 traceback | **`--once` 在 Foxy 不存在**，或没 source 到 `unitree_go` 消息包 |
| 话题在，但收不到数据 | QoS 不匹配；或**机载电脑刚启动、SLAM 还没起**（`uptime` 看一眼） |
| **小消息能收、大消息收不到** | ⚠️ **已知问题，不是你的错** —— 见下方「大消息静默」 |
| `ping 10.31.111.3` 不通 | **正常** —— 狗只放行 Tailscale，走 100.x |

### ⚠️ 已知问题：原生大消息通路不可靠

**现象**：小消息正常，点云/视频这类大消息收不到。

| 消息大小 | 例子 | 实测 |
|---|---|---|
| 小（几百字节） | `/sportmodestate` | ✅ 正常 |
| **大**（点云、视频） | `/utlidar/cloud`、`/frontvideostream` | ❌ 收不到 / CDR 报 `invalid data size` |

**这不是你配错了。** 前人已经撞上过，并为此自建了 `baiyanggo_webrtc_bridge`
（它的 README 原话：「狗的 **DDS 转发静默时**的自建数据通路」）。

**根因假设（⚠️ 待验证，未经许可不要改）**：`~/cyclonedds_ws/cyclonedds.xml` 里

```xml
<Internal>
    <!--MinimumSocketReceiveBufferSize>50MB</MinimumSocketReceiveBufferSize-->
</Internal>
```

**接收缓冲被注释掉了** —— 大消息溢出丢包。内核是放行的（`rmem_max = 50MB`）。

> ⚠️ 这是**推论不是定论**。验证要取消注释并重启 DDS —— **那会改动狗上的配置，
> 先问过管理这只狗的人**（见 `设备清单.md` §7 的待问清单）。

🔴 **但注意：`baiyanggo_webrtc_bridge` 是必需的**（实验室成员确认，2026-09-18）。

**所以别想着"取消那行注释就能不靠桥"** —— 那条路前人已经判定过，
**要拿点云/视频，就走桥**。

**桥的用法**：订阅 `/baiyanggo/webrtc/voxel_map`。
⚠️ 它是**体素化产物**（无逐点时间戳/intensity），且**狗静止时不推送**
（运动门控）—— 调它的时候别以为是坏了。
