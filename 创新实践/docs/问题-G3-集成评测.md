# G3 · 集成评测问题看板

> 最后复核：2026-10-07  
> 范围：`baseline/g3_integration_eval/` 及已有联调产物  
> 口径：只记录能从当前代码、测试或 rosbag 独立复核的问题。

## 1. 结论

G3 目前有 **23 项待处理问题**，另有 **1 项已修复**。两条主线是：

1. **安全闭环不完整**：ESTOP 和退出 RETURN 都不会取消 G3 已发出的返航目标，电量链路也没有超时看门狗。
2. **评测结果不可直接用于验收**：覆盖率可以算出假 100%，导航成功率把主动抢占算成失败，检出率和误检率尚未实现。

建议先完成 **A（安全与返航生命周期）**，再完成 **B/C（电量健康与评测可信性）**；Mission Brain 接线放在基础闭环稳定之后。

## 3. 建议拆成的工作包

### A. 返航安全与生命周期（最先）

**包含**：H1、M6、M7、M8、L1。

- 保存 accepted goal handle 和 attempt context，提供幂等异步 `cancel_current_goal()`。
- ESTOP 和离开 RETURN 都必须取消当前 goal。
- 不在订阅回调里同步等 action server。
- 导航终态回流状态机：成功后进入 STANDBY，失败进入明确的重试/失败策略。
- 在广播 RETURN 前验证 home frame/x/y/yaw 的类型和有限性。

**验收**：accepted 返航 goal 执行中发 ESTOP，bag 中必须出现 cancel 终态，`cmd_vel` 在限时内归零；Nav2 server 不在时，ESTOP 不得等待 server timeout。

### B. 电量健康链路

**包含**：M3、M4、M5。

- 记录最后一条有效 BatteryState 的 ROS 时间，EXPLORE 中超时后进入明确安全态并发布事件。
- `present=false`、NaN/inf、越界和超时必须有可区分的诊断。
- 修改 `publish_test_battery.sh`，测试消息显式设置 `present=true`。

**验收**：正常 0–1 电量、越界/NaN/Inf 电量、`present=false`、话题中断和仿真时钟回退均有独立测试。

### C. 评测可信性

**C1 覆盖率：H2、H3、M2、M10、M12**

- 按 ROS map YAML 语义解码 `mode/negate/free_thresh/occupied_thresh`。
- 报告记录两张图的阈值、分辨率、origin 及 canvas 重合率。
- 异常时仅将 coverage 降级为 `unavailable`，仍生成其余报告。

**C2 导航/返航成功率：H4、M1、M9、M11、M12**

- 用 `/g3/return_event.goal_id` 从普通导航指标中排除返航 goal。
- RETURN accepted 后立即 canceled/aborted 的旧探索 goal 归入 `preempted`。
- 有 incomplete/conflict 或 bag 截断时，指标降级为 `unavailable`。
- 更新将 aborted/canceled 无条件算失败的旧测试断言。

**C3 检测指标：H5、M12**

- 定义 ground truth 输入格式和 CLI 参数，冻结时间、类别、空间匹配与去重口径。
- 实现 detection rate 和 false-positive rate。
- 与 G2 冻结 Detection3D 真值标注和匹配规则。

### D. Mission Brain 接线与可观测性

**包含**：B1、B2、B3。

- 统一 `EXPLORE` 与 `exploring` 的边界语义。
- 补 context/candidates 发布器和 decision 消费者，但 Brain 仍不能越过硬护栏直接控制 `cmd_vel`。
- 记录 provider/model、延迟、超时/解析/校验结果、原始输出摘要和最终决策。

## 4. 核心证据

### H1：ESTOP 不取消 G3 在飞返航 goal

- `navigate_to_pose_client.py` 不保存 accepted goal handle，也没有 `cancel_goal_async()` 路径。
- `state_machine_node.py::_apply_event()` 进入 ESTOP 时只打日志。
- G2 会取消自己的探索 goal，但 G3 自己发出的返航 goal 仍在执行。

这不只是“逻辑急停不等于物理急停”；即使只看 Nav2 任务层，ESTOP 也没停止已发目标。

### H2/H3：覆盖率图像语义错误

`coverage.py` 硬编码 `FREE_PIXEL=254` / `UNKNOWN_PIXEL=205` / `OCCUPIED_PIXEL=0`，不读 map YAML 的阈值与模式。已复现：

| 输入 | 当前输出 |
|---|---|
| SLAM 图全 0（全 occupied） | 100% |
| SLAM 图自由灰度为 255 | 100% |
| 参考图 8 格 254 + 8 格 253，仅前 8 格被观测 | 100%（真值 50%） |

G1 实图按 `free_thresh=0.196` 得到的分母是 77,014；换成 0.25 是 311,853，相差 4.05 倍。

### H4/M1：抢占和截断使导航成功率失真

`auto_discharge_return_20260926_193627` 的时序：

| bag 时间 (ns) | 事件 |
|---|---|
| 1790422598458241552 | 探索 goal `181a8148…` EXECUTING |
| 1790422726250619812 | `/mission_state=returning` |
| 1790422726255170972 | 返航 goal `2529f011…` accepted |
| 1790422726260773317 | 旧探索 goal ABORTED（accepted 后 5.6 ms） |
| 1790422883592717236 | 返航 goal SUCCEEDED |

当前的 0.5 实际是“1 个返航成功 ÷（1 个返航成功 + 1 个主动被抢占的探索 goal）”。若 bag 在任务中途停止，结果还会在 0、0.5 和 1 之间改变。

### H5：检出率和误检率未实现

`evaluate_bag.py` 对 `detection_rate` 和 `false_positive_rate` 始终传入 `None`。CLI 没有 ground-truth 参数，代码也没有匹配逻辑。

### M4/M5：电量链路缺少健康判定

- 节点不保存最后电量时间，话题中断后无告警、无状态转移。
- `_on_battery()` 不检查 `message.present`，默认的 `percentage=0.0` 可误触发 RETURN。
- `scripts/publish_test_battery.sh` 只填 `percentage`，需一起修正。

### M6/M8：RETURN 无出口，离开时也不清理 goal

`NavigateToPoseClient` 的 event callback 只连到 `_publish_return_event()`，不改状态机。因此：

- succeeded 后仍是 RETURN，`/mission_state` 仍是 `returning`；
- aborted/rejected/server_unavailable 后没有重试或失败态；
- 人工 standby 后旧返航 goal 仍在执行；
- 再次 explore 且电量仍低时，可发出第二个返航 goal。

仿真电池的“到站充电”只改电量，没有解决状态机卡在 RETURN 的问题。

### M7：action server 等待阻塞安全命令

`request_return()` 在电量订阅回调的调用链中执行 `wait_for_server()`，主程序使用单线程 `rclpy.spin()`。这不会永久死锁，但会让 ESTOP 和后续电量消息在 timeout 窗口中排队。

### M2/M9/M10：异常输入被伪装成正常指标

- 两图完全不重合时，当前会报 `available=true, value=0.0`。
- 同一 goal/attempt 出现多个终态时，当前剔除 conflict 后继续报成功率。
- `calculate_coverage()` 异常没有在指标层捕获，会使整份报告无法落盘。

### B1/B2/B3：Mission Brain 实现存在，但还没有进入系统闭环

- `/mission_state` 的跨组值是 `standby/exploring/returning/estop`，Brain 却只接受 `EXPLORE`；`exploring.upper()` 是 `EXPLORING`，因此会恒定回退为 WAIT。
- `/mission/context` 和 `/exploration/candidates` 无发布者，`/brain/decision` 无消费者。
- `BrainDecision.to_dict()` 没有延迟、错误类型和原始输出摘要。

## 5. 已确认正常的能力

- `battery_adapter.py` 的 Unitree SOC 0–100 → BatteryState 0–1 换算和边界检查正确。
- `sim_battery.py` 能处理首帧、零时钟和仿真时钟回退。
- 返航前先广播 `/mission_state=returning`，再等待/发送 Nav2 goal，顺序正确。
- `enable_navigation_transmission=false` 时发送路径不可达，默认为 preview-only。
- ESTOP 的逻辑状态转移优先级正确；问题是进入后没有取消底层 goal。
- `attempt_id` 的异步回调不会串台，导航异常会转成带 `detail` 的事件。
- 历史 goal 过滤、坐标映射、除零保护和 bag 时长/消息数统计在已复核样本上成立。

## 6. 建议交付顺序

1. **A：H1 + M6 + M7 + M8 + L1**，一次性建立返航 goal 的完整生命周期。
2. **B：M4 + M5**，补齐电量断链和无效消息的安全处置。
3. **C1：H2 + H3 + M2 + M10 + M12**，先让覆盖率可信且不拖垮整份报告。
4. **C2：H4 + M1 + M9 + M11 + M12**，冻结抢占、截断和 conflict 口径。
5. **C3：H5 + M12**，与 G2 一起冻结真值和检测匹配规则。
6. **D：B1 + B2 + B3**，最后接入 Brain。
7. **L2/L3/L4** 与所属模块顺手关闭，不单独拆迭代。
