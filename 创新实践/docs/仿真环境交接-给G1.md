## 二、⚠️ enroot 的两个坑（G1 一定撞，已踩平）

### ① enroot **不把环境变量带进容器**

```
FOO=bar ~/.enroot/ros bash -c 'echo $FOO'   →  容器里是空的
```

所以 `DISPLAY` / `XAUTHORITY` **必须走 `-e`**，`export` 没用。

### ② NVIDIA 要两个环境变量，少一个都不行

```
NVIDIA_VISIBLE_DEVICES=all        ← 不设，98-nvidia.sh 钩子直接跳过，容器里 0 个 NVIDIA 库
NVIDIA_DRIVER_CAPABILITIES=all    ← 默认只有 utility/compute，**不含 graphics**，
                                    于是 libnvidia-glcore 不注入，渲染起不来
```

两个都设 → 36 个库注入，含 `glcore/eglcore/glsi`。

**已经封装好了**：`~/.enroot/ros-gui`（不动原来的 `~/.enroot/ros`）。
源码里有注释解释这两个变量为什么这么设。

## 三、⚠️ 建仓库时撞到的三个坑

### ① `go1_description` 会让 rosdep **整体失败**

照着仓库 README 敲 `rosdep install --from-paths src` 会报：

```
go1_description: Cannot locate rosdep definition for [ros_ign_utils]
```

**而这个包是 Go1 的遗留，Go2 用不到。** 关键是 —— rosdep 是**先全部解析、再统一安装**，
所以只要它在扫描路径里，**一个依赖都装不上**，报错还看起来像"缺包"。

绕法（不改仓库）：

```bash
rosdep install --from-paths \
    src/go2_description src/gazebo_sim src/quadropted_msgs \
    src/quadropted_controller src/navigation2 src/cartographer \
    --ignore-src -y
```

编译时同理：`colcon build --packages-skip go1_description`

### ② ⭐ `transforms3d` 用了被移除的 `np.float` → **控制器崩溃 → 狗塌了**

这是**最难查的一个**，因为报错指向的位置和根因隔了三层：

```
robot_controller_gazebo.py
  → RobotController.py: import tf_transformations
    → transforms3d/quaternions.py:26:  _MAX_FLOAT = np.maximum_sctype(np.float)
      → AttributeError: module 'numpy' has no attribute 'float'
```

`np.float` 在 NumPy 1.24+ 被移除，而 apt 装的 `transforms3d` 还在用。
**后果：`robot_controller_gazebo.py` 和 `QuadrupedOdometryNode.py` 两个进程直接死**，
腿没有力矩 → **狗塌在地上**。

**修法**（改容器，不动仓库）：

```bash
~/.enroot/ros --root pip3 install -U transforms3d     # 升到 0.4.2
```

### ③ `controller_manager` 的 spawner 竞争 → 腿控制器停在 `unconfigured`

```
[spawner] Failed getting a result from calling load_controller in 10.0. (Attempt 1 of 3.)
[ign gazebo] Loading controller 'joint_group_controller'
[ign gazebo] ERROR: A controller named 'joint_group_controller' was already loaded
[spawner-9] FATAL: Failed loading controller joint_group_controller
```

服务响应慢 → spawner 超时重试 → 撞上"已经加载了" → FATAL 退出。
**结果 `joint_group_controller` 停在 `unconfigured`，腿照样没力矩。**

**运行时救回来**（不用重启仿真）：

```bash
ros2 service call /robot1/controller_manager/configure_controller \
  controller_manager_msgs/srv/ConfigureController "{name: joint_group_controller}"
ros2 service call /robot1/controller_manager/switch_controller \
  controller_manager_msgs/srv/SwitchController \
  "{start_controllers: [joint_group_controller], stop_controllers: [], strictness: 2}"
```

查状态：`ros2 service call /robot1/controller_manager/list_controllers controller_manager_msgs/srv/ListControllers`
（两个都要 `state='active'`）

## 五、🔴 给 G2 自己的那条结论（不是给 G1 的，但记在这免得丢）

**`fit_floor_plane` 假设「内点最多的平面就是地面」—— 这个假设在前视低机位下不成立。**

实测（仿真，前视相机离地约 0.4 m、俯仰 0）：

```
深度图按行分布：顶部 0.26 m → 中部 6.6 m → 底部 7.4 m
                （越往下越远 = 看到的是墙/天花板，不是俯视地面）
拟合结果：     相机离地 -6.79 m（平面跑到相机上方 6.8 m）
               不让下方比 48.3% < 50% → 被 not_at_bottom 挡下
```

在 `1378` 素材上这个假设成立（Kinect 架在 2.44 m **俯视**，地面占大半画面），
**但真机是前视低机位（离地 35 cm、俯仰 0°）** —— 和仿真一样的几何。

**所以这条不是"仿真没配好"，是对真机同样成立的结构性问题。**

> 📌 这条已经从本文档**移进 G2 自己的文档**：
> `baseline/g2_vision_explore/docs/真实RGB-D素材实测-1378.md` **§4.7**。
> 那儿是它的正式位置（含「待定」的几个解法方向）。
> G2 的代码里也加了指针：`g2_core/floor.py` 模块 docstring。

## 六、VNC（共用的，不只是仿真用）

```
display :2   端口 5902   密码 311311
配置         ~/.vnc/xstartup（XFCE 会话）
```

**三个坑**：

1. **`~/.vnc/xstartup` 不写的话会起 GNOME** → 卡在登录界面且**吃不进键盘**。
   已改成 XFCE（无登录界面）。**这个文件是共享的，改之前问一声。**
2. **窗口可能是"创建了但没显示"**（`xwininfo` 里 `Map State: IsUnMapped`）。
   调出来：`DISPLAY=:2 xdotool windowmap <窗口id> && xdotool windowsize <id> 1200 750`
3. ⚠️ **仿真跑着的时候不要重启 VNC** —— 会把 `:2` 整块屏幕拆掉，
   正在画图的 Gazebo / rviz2 因 `X11 connection broke` 一起死，整条 launch 连锁退出。
   （2026-09-18 我自己踩的）

**外面连不进来**：服务器的 5902 被防火墙挡着（只有 22 通）。
走 **VS Code 的端口转发**（终端旁边的「端口」面板 → 转发 5902），
