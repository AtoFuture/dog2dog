## 2. 本次收尾做了什么

### 2.1 网页工作台

- 交互化：工具栏「交互」在 `交互已开启` / `仅查看` 之间切换；服务端 `--view-only` 可强制只读。
- 「找机器狗」：`POST /api/view/robot` → 检查 `/world/<world>/scene/graph` 中存在目标 model →
  调用 `/gui/move_to`。只接受 loopback 同源、无请求体；仅查看下 403。
- 修 `--world` / `--robot-model` / `--partition` 参数，去掉 `world_demo`、`robot1_my_bot` 的硬编码假设。
- 修 **enroot 环境隔离**：宿主 `IGN_PARTITION` 不会进入容器，找机器狗改为在容器内
  `env IGN_PARTITION=... GZ_PARTITION=... ign service ...`；服务超时返回 502，不再误报 409。
- 修 **电量 QoS 不兼容**：`/runtime/battery_state` 是 BEST_EFFORT，观察节点改为传感器 QoS，
  否则电量面板永远为空。
- 新增 `--ros-env KEY=VALUE`，让观察节点能加入 CycloneDDS 运行栈。
- 新增 `npm run test:browser`（无头 Chrome/CDP），覆盖 VNC 真实像素、遥测面板、交互开关、
  找机器狗、重连、移动端和页面错误。
- README 同步为「可交互工作台」，并写明 ROS 遥测的前置条件。

### 2.2 仿真联调

今天在隔离域 **227**、partition **webdemo227** 上实际拉起了：

1. Gazebo GUI（`world_demo`，仓库场景）；

4. 网页工作台（同一 Domain / partition / CycloneDDS 配置）。

实跑结果：DeepSeek 连续选点、Nav2 执行、机器狗真实移动、地图增长；

G3 走 RETURN 交接并回到 STANDBY。

## 3. 演示启动步骤

> 以下命令按本机环境写死；换机器时改 `SIM_WORKSPACE`、`OUT`、`DOMAIN`、`PARTITION`、`DISPLAY`。
> 所有目录必须为 ASCII。容器内仓库路径是 `/home/wy/project`（宿主 `/home/wy/data1/创新实践` 的 bind mount）。

```bash
SIM_WORKSPACE=/home/wy/go2_sim_ws/ROS2-Gazebo-GO2
NAV=/home/wy/data1/创新实践/external/go2_real_robot/qwen_robotnav
OUT=/home/wy/data1/.runtime/web_console_demo
DOMAIN=227
PARTITION=webdemo227
DISPLAY_NUM=2
CYCLONE=file://$SIM_WORKSPACE/src/docker/cyclonedds.xml
```

### 3.1 准备私有配置（只需一次）

```bash
cd "$NAV"
SLAM_ROS_DOMAIN_ID=$DOMAIN SLAM_IGN_PARTITION=$PARTITION \
  ./scripts/run_slam_frontier.sh "$OUT" 5 --prepare-only
```

生成 `$OUT/gazebo_nav2.launch.py`、`$OUT/slam_navigation.launch.py`、`$OUT/nav2.yaml` 等。

### 3.2 启动 Gazebo 服务端 + 传感器/控制器（headless，但加载 gz_ros2_control）

```bash
setsid /home/wy/.enroot/ros-gui bash -c '
source /opt/ros/humble/setup.bash
source /home/wy/go2_sim_ws/ROS2-Gazebo-GO2/install/setup.bash
export ROS_DOMAIN_ID=227 IGN_PARTITION=webdemo227 GZ_PARTITION=webdemo227
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml
export GZ_SIM_RESOURCE_PATH=/home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/gazebo_sim/models
export GZ_HEADLESS=1
export __EGL_VENDOR_LIBRARY_FILENAMES=/tmp/gz_egl/10_nvidia.json
export PYTHONPATH=/home/wy/project/external/go2_real_robot/qwen_robotnav:${PYTHONPATH:-}
exec ros2 launch /home/wy/data1/.runtime/web_console_demo/gazebo_nav2.launch.py \
  sensors:=true world:=warehouse.sdf
' > "$OUT/sim_headless.log" 2>&1 < /dev/null &
```

等日志出现 `System Successfully configured!` 与 `Loading controller_manager`，并确认控制器 active：

```bash
/home/wy/.enroot/ros bash -lc 'source /opt/ros/humble/setup.bash; export ROS_DOMAIN_ID=227 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml; ros2 service call /robot1/controller_manager/list_controllers controller_manager_msgs/srv/ListControllers'
```

`joint_group_controller` 与 `joint_state_broadcaster` 都应为 `active`。

### 3.3 启动 GUI 客户端（单独进程，不拉 RViz）

```bash
setsid /home/wy/.enroot/ros-gui bash -c '
source /opt/ros/humble/setup.bash
source /home/wy/go2_sim_ws/ROS2-Gazebo-GO2/install/setup.bash
export IGN_PARTITION=webdemo227 GZ_PARTITION=webdemo227
export GZ_SIM_RESOURCE_PATH=/home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/gazebo_sim/models
exec ign gazebo -g -v3 --render-engine ogre2
' > "$OUT/gui.log" 2>&1 < /dev/null &
```

等 GUI 窗口出现（`xwininfo -root -tree | grep '"Gazebo"'`）。GUI 客户端连接 3.2 的服务端，
因此场景、机器人和物理状态都来自同一份仿真。

确认 `odom → base_link` 已出现：

```bash
/home/wy/.enroot/ros bash -lc 'source /opt/ros/humble/setup.bash; source /home/wy/go2_sim_ws/ROS2-Gazebo-GO2/install/setup.bash; export ROS_DOMAIN_ID=227 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml; ros2 run tf2_ros tf2_echo odom base_link --ros-args -r /tf:=/robot1/tf -r /tf_static:=/robot1/tf_static'
```

> **坑（2026-10-17 实测）**：**必须用顶层 `gazebo_nav2.launch.py` 起服务端**。
> 手工 `ign gazebo -r` 不会加载 `gz_ros2_control`，表现为控制器/commands 都正常、
> 狗原地动腿，但 Gazebo 里 `robot1_my_bot` 的模型根位姿不动，真值路径恒 0。
> GUI 用单独的 `ign gazebo -g` 客户端，避免顶层 launch 在 GUI 模式默认拉起 RViz
> （RViz 异常退出会带走整个 sensor launch，Nav2 报 `Invalid frame ID "odom"`）。

### 3.4 启动统一运行栈

```bash
rm -f "$OUT/runtime_manifest.json" "$OUT/runtime_exit.json"
setsid /home/wy/.enroot/ros bash -c '
source /opt/ros/humble/setup.bash
source /home/wy/go2_sim_ws/ROS2-Gazebo-GO2/install/setup.bash
source /home/wy/data1/.runtime/web_console_demo/progress_install/local_setup.bash
export ROS_DOMAIN_ID=227 IGN_PARTITION=webdemo227 GZ_PARTITION=webdemo227
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml
export PYTHONPATH=/home/wy/project/external/go2_real_robot/qwen_robotnav:/home/wy/project/external/go2_real_robot/qwen_robotnav/ros2_ws/src/qwen_robotnav_ros:/home/wy/project/baseline/g3_integration_eval:/home/wy/project/baseline/g2_vision_explore:/home/wy/project/baseline/g2_vision_explore/vision_explorer:${PYTHONPATH:-}
set -a; source /home/wy/data1/创新实践/.env; set +a
export MISSION_BRAIN_API_KEY="${MISSION_BRAIN_API_KEY:-$DEEPSEEK_API_KEY}"
exec python3 /home/wy/project/external/go2_real_robot/qwen_robotnav/scripts/run_navigation_runtime.py \
  --profile /home/wy/project/external/go2_real_robot/qwen_robotnav/config/sim_runtime.yaml \
  --navigation-dir /home/wy/data1/.runtime/web_console_demo \
  --expected-domain 227 --enable-motion
' > "$OUT/runtime_supervisor.log" 2>&1 < /dev/null &
```

等 `$OUT/runtime_*_log` 出现、`/mission_state` 为 `standby`、`/robot1/map` 有数据。

### 3.5 启动网页工作台

```bash
cd /home/wy/data1/创新实践/external/go2_real_robot/qwen_robotnav/web_console
setsid python3 server.py --display :2 --domain 227 --partition webdemo227 \
  --world world_demo --robot-model robot1_my_bot \
  --ros-env RMW_IMPLEMENTATION=rmw_cyclonedds_cpp \
  --ros-env CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml \
  --log-dir /home/wy/data1/.runtime/web_console_demo/console \
  > /home/wy/data1/.runtime/web_console_demo/console/server.log 2>&1 < /dev/null &
```

打开 **http://127.0.0.1:8765**。远程访问用 SSH 隧道：

```bash
ssh -N -L 8765:127.0.0.1:8765 wy@服务器地址
```

### 3.6 开始探索

```bash
/home/wy/.enroot/ros bash -lc 'source /opt/ros/humble/setup.bash; export ROS_DOMAIN_ID=227 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp CYCLONEDDS_URI=file:///home/wy/go2_sim_ws/ROS2-Gazebo-GO2/src/docker/cyclonedds.xml; ros2 topic pub --once /g3/command std_msgs/msg/String "{data: EXPLORE}"'
```

页面任务状态应变为「探索中」，地图、位姿、事件开始更新。

### 3.7 停止顺序

1. `Ctrl+C` / SIGINT 运行栈 supervisor（它会先停 G2/G3/Nav2，最后让 guard 发零并退出）；
2. 停 sensor launch；
3. 停 `ign gazebo`（server+GUI）；
4. 停网页控制台（它只清理自己的 x11vnc/websockify/观察节点）。

## 5. 项目现状（按证据）

### G1 建图导航

- 历史 AMCL + 静态地图导航有 11/11 action 成功记录，但报告没有真值 ATE/覆盖率，
  且 `go2_nav2.yaml` 的 `bt_navigator.odom_topic=/g1/ground_truth` 把仿真真值接进了导航。
- **P1 第 5 项 2026-10-17 连续 3 次 e2e 通过**（3/4/5 m，各自从干净仿真出发）：
  `tools/nav2_scaled.launch.py` 已修 `scan_topic=/robot1/velodyne`、SLAM 模式只起
  `navigation_launch.py`、补 `/tf` 与 `/map` 重映射；三次真值前进分别为
  3.007 / 4.001 / 5.001 m，地图 3.7→41.4 / 44.8 / 47.9 m²。证据在
  `.runtime/g1_slam_e2e_20261017/`。**仍限同一仓库直线场景**，转向、不同场景、
  更长距离与重复统计尚未覆盖，不能当作全场稳定验收。
- 运行前提：必须用顶层 `gazebo_nav2.launch.py` 起仿真以加载 `gz_ros2_control`；
  手工 `ign gazebo` 会让狗原地动腿、模型根位姿不动（2026-10-17 实测）。
- 静态矩阵：`static_suite_v3` 3/6、`trajectory_suite_v4` 3/6；窄通道归位/净空、不可达场景
  终止原因未稳定通过。文档已明确「当前版本仍未完整通过静态导航验收」。

### G2 视觉探索

- frontier 选点、测地路径、路径净空、候选评分/黑名单、`NavigateToPose` 均为真实实现，
  单测与历史仿真正例较多（人员 3D 误差约 0.14 m）。
- 正式运行栈只启动 `vision_explorer`；检测/侦察/倒地只在 `SLAM_LEGACY_VALIDATION=1`
  的 legacy 入口启动，**检测链路没有进入当前统一运行栈**。
- 倒地判据仍是研究性结论（方法 A 召回约 43%，方法 B 阈值不能同时满足高召回/低误报）。
- 真机 H.264 桥只做了离线验证；真机 CameraInfo、深度、外参、QoS、Foxy/Humble 兼容未验证。

### G3 集成评测

- 状态机（STANDBY/EXPLORE/RETURN/PAUSED/ESTOP）、低电量返航、ESTOP/离航取消、
  RETURN 交接、自主结束探索均有实跑证据。
- 覆盖率/检出率/误检率/ATE 的口径已实现或部分实现，但并非所有运行都提供参考图和真值，
  不能把历史 `available=false` 的指标当作通过。
- Brain 已进入统一运行栈（DeepSeek 候选排序 + 确定性回退），不再是孤岛。

### 统一运行栈

- 7 进程链：guard、battery、scaler、G3、SLAM/Nav2、Mission Brain、G2 frontier。
- 普通仓库基线 `trajectory_baseline_v5`：18/18、2 目标、3 次 DeepSeek/0 回退、
  归位 0.305 m、7 子进程 exit 0。
- 自主闭环 `autonomous_completion_v1`：15/15、7 个完成目标/5 个有效目标、
  8 次 DeepSeek/0 回退、返航真值误差 0.2338 m。
- 静态矩阵仍 3/6，不能宣称全部场景稳定完成。

### 网页工作台

- 镜像现有 Gazebo 窗口，不启动新仿真；ROS 侧只读。
- 交互/仅查看、找机器狗、截图、全屏、重连、移动端均实测通过。
